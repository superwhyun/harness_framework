# Harness execution units

목표: 큰 작업을 명시적 단위로 나누고 현재 Claude·Codex 세션에서 구현·검증하며 진행한다.
범위: task 스캐폴드, 프로젝트 규칙·도구 진입점·문서·전역 독립 스킬. 기존 phase 기록과 호환 도구 보존.

## 설계와 결정

- 사용자 요청은 현재 도구에서 하네스를 사용하는 것이다. 별도 모델 CLI 호출을 추가한 이전 구현은 의도와 달라 제거했다.
- 단위 분해는 유지한다. task 하나에 범위·완료 조건·의존 관계·검증 방법·상태·실제 결과를 남긴다.
- 도구의 내장 개발 루프를 사용한다. 단위별 상태 전환과 검증은 에이전트가 수행하는 절차이며 외부 강제 게이트로 표현하지 않는다.
- 기존 GPT/Claude 두 호출 샘플 검증은 제거한 배치 방식의 과거 근거이며 현재 세션 방식의 검증으로 사용하지 않는다.

## 실행 단위

- 완료 조건: 새로운 작업 흐름에 별도 모델 호출 경로가 없고 legacy 호환 동작은 유지된다.
- 검증 방법: 참조 검색, legacy 회귀 테스트.
- 검증 결과: 전체 81개 회귀 테스트 통과, 기본 흐름의 실행기 참조 없음. legacy 실행기 테스트 유지.

### 02. 계획과 스킬 현행화

- 상태: completed
- 범위: Markdown 단위 스캐폴드, 문서·도구 진입점·전역 스킬 갱신.
